# 目标

生成成功后，形象目录自动具备可展示的封面和静默预览片；用户资产卡与首页未连麦时不再空白。补写只使用已有 `full_imgs` 抽帧，不重跑口型。

# 范围

- 生成任务成功后：若缺少 `cover.jpg` / `preview.mp4`，从 `full_imgs` 写出它们并刷新形象元数据
- 启动扫描时：已有 `full_imgs` 但缺封面或预览的目录同样补写；已有文件不覆盖
- 用户「我的资产」有预览片时静音循环播放，封面作 poster；没有预览片时仍显示静态封面
- 用户首页未连麦时同样：有预览则静音循环，否则静态封面
- 管理员单独走生成接口（无订单）成功后也补写并入库

# 非目标

- 不改口型模型，不实现图+音频自动变口型
- 不把管理员首页迁入 WebRTC 演示台
- 不覆盖已有 `cover.jpg` / `preview.mp4`
- 不归档 `omni-local-tts`，不改用户改密
- 不改原 `web/`

# 验收示例

- A1：生成成功后（含测试假任务）目录出现 `cover.jpg` 与 `preview.mp4`；已登录可访问的封面/预览媒体接口返回成功；用户资产列表带上 `cover_url` 与 `preview_url`
- A2：资产卡在有 `preview_url` 时静音循环播放预览，封面作 poster；仅有封面时仍显示静图
- A3：用户首页未连麦时，已发布形象有预览则静音循环，否则显示封面
- A4：已有 `full_imgs` 但缺封面/预览的目录，在扫描后被补齐；已存在的 `cover.jpg` / `preview.mp4` 不被改写
- A5：生成失败不写出封面/预览；未登录或无权访问媒体仍为 401/404；原 `web/` 不变

# 约束与不变量

- 工作区：`.worktrees/avatar-preview-media`，基于已合入管理员待办的 main
- `omni-local-tts` 仍占用 main 的 current 隔离
- 预览约 5 秒、无声；帧不足则用全部帧
- 单测不依赖 GPU；可用假任务或直接调用补写函数，不要求真实浏览器能播编码细节

# 决策

- 隔离：独立 worktree
- 素材来源：现有 `full_imgs`，不重抽源视频、不重跑检测
- 已有封面/预览不覆盖
- 资产与首页：预览优先循环，封面作 poster
- 扫描也会补写旧目录，避免只有新生成才有预览
