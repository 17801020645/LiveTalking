# 目标

把后端从「演示级内存状态」收成可运维的产品切片：生成任务可落盘、探活可用、跨域不再 `*`，管理员 TTS 页经 8010 代理 Omni，局域网浏览器不必直连 8091。

# 范围

- 生成任务写入 SQLite，进程重启后仍能列出历史状态
- 公开 `GET /healthz`
- CORS 默认同源，可用环境变量追加白名单；当前 Host 对应源自动放行
- 管理员「TTS 语音管理」经 8010 代理 Omni 的音色列表、合成、上传与删除

# 非目标

- 不改口型模型、不改用户连麦交互
- 不开放自助注册、不支付
- 不重写原 `web/tts/` 整页（该页仍可直连 8091）
- 不把数字人默认 TTS 切到 `omnitts`
- 不探测 GPU / Omni 是否健康（`/healthz` 只证明 8010 进程可响应）
- 不重做已有的订单上传大小限制与全局 `max_session`

# 验收示例

- A1：写入一条生成任务后重启进程，任务列表仍能看到该任务及其状态字段
- A2：进程退出时仍为 `pending`/`running` 的任务，下次启动后列出为 `failed`，并带可理解说明
- A3：未登录 `GET /healthz` 返回 200，响应体不含密钥、口令或会话 Cookie
- A4：请求 `Origin` 等于当前 Host 对应源时，带 Cookie 的跨资源请求可拿到允许凭证的 CORS 头；未在白名单的 Origin 不会被 `*` 放行
- A5：环境变量可追加额外 Origin，该 Origin 带凭证请求可通过 CORS
- A6：已登录管理员在 `/app/admin/tts` 不填写 8091 地址即可拉取音色列表（测试可用假上游）
- A7：管理员经 8010 发起合成，成功时得到音频；上游不可达时得到明确失败，而不是无限等待
- A8：未登录访问 TTS 代理为 401；普通用户为 403

# 约束与不变量

- 工作区：`.worktrees/platform-hardening`，基于已合入连麦的 main
- `omni-local-tts` 仍占用 main 的 current 隔离；本 change 不改 Omni 进程
- 不把密钥写入 Git
- 单测不依赖真实 8091 或 GPU

# 决策

- 隔离：独立 worktree
- 订单上传校验与全局会话上限沿用现有实现
- TTS：管理员页经 8010 服务端代理 Omni；浏览器只访问 8010
- CORS：默认同源；自动放行与当前请求 Host 匹配的 Origin；`LIVETALKING_CORS_ORIGINS` 追加白名单
- healthz：公开，无密钥
- 中断中的生成任务：下次启动标记 `failed`，不自动续跑
- 任务列表/查询/删除与创建一样，仅管理员
