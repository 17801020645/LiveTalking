# 目标

管理员在管理后台可以对普通用户点「删除」（经确认）。活跃或已禁用均可。删除后该账号从用户表消失，不能再登录；其会话、订阅和订单一并删除。已生成的形象目录仍保留。不能删除管理员或当前登录账号。

# 范围

- `POST /api/v1/admin/users/{user_id}/delete`：仅 `role=user`；成功后删除该用户及其 sessions、subscriptions、orders
- 管理后台用户表：普通用户行显示删除按钮（经确认）；管理员行没有
- 更新 `auth-rbac`、壳层管理后台一句，以及 README 管理员说明

# 非目标

- 不自助注册、不邮箱、不代人改密
- 不改 `web/`，不改 `README-EN.md`
- 不删磁盘上的形象目录；不要求清掉订单上传文件
- 不恢复幽灵 change `omni-local-tts`

# 验收示例

- A1：管理员删除活跃或已禁用普通用户后，用户列表不再有该行；用原密码登录失败（与错误密码同一文案）
- A2：删除管理员、当前登录账号或不存在的 id 失败；未登录 401，普通用户 403
- A3：普通用户行有删除按钮并经确认；管理员行没有。删除后该用户订单不再出现在管理员订单表
- A4：原 `web/` 无改动

# 约束与不变量

- 工作区：main 当前目录（`isolation: current`）
- SQLite 外键已开启；删用户前清 sessions / subscriptions / orders
- 单测不连浏览器

# 决策

- 切片：管理员删除普通用户
- 隔离：当前目录 main
- 活跃与已禁用均可删，经确认
- 订单随用户删除；已生成形象留在目录
- 接口形态对齐禁用/启用：`POST .../delete`
