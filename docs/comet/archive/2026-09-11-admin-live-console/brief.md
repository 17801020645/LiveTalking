# 目标

管理员有独立「演示连麦」页：选形象、建立 WebRTC、看画面并发 echo 文字、打断。首页只展示待办。原站点 `/` 仍可匿名打开完整旧控制台。

# 范围

- 管理员首页只保留三张待办卡片，并提供进入演示页的入口
- 侧栏在首页后增加「演示连麦」，路由 `/app/admin/live`
- 演示页两栏：左选形象/连接/画面，右发文字（Echo 或 Chat）与打断；未选形象不能开始
- 信令沿用现有匿名 `POST /offer`、`POST /human`、`POST /interrupt_talk`
- 演示页保留「打开 /」，供音频上传、录制、动作编排
- 普通用户首页仍走已发布形象的 `/api/v1/me/offer`

# 非目标

- 不把音频上传、录制、参考音频、动作编排迁进 `/app`
- 不把原 `web/index.html` 整页嵌入或逐控件搬运
- 不改口型模型、不接入麦克风 ASR
- 不收紧匿名 `/offer`，不改原 `web/`
- 不归档 `omni-local-tts`

# 验收示例

- A1：管理员首页只有三张待办卡片和「去演示连麦」入口；没有「开始连接」、发文字或打断
- A2：侧栏第二项为「演示连麦」；`/app/admin/live` 有选形象、开始连接、发文字、打断，以及「打开 /」；未选形象时不能开始
- A3：管理员选择已入库形象后可发起 `/offer`，请求带上该 `avatar`；连接后发文字走到 `/human`，`type` 为 `echo` 且带 `sessionid`
- A4：打断请求走到 `/interrupt_talk` 并带上本次 `sessionid`
- A5：普通用户首页仍是已发布形象 + `/api/v1/me/offer`；用户打不开管理员演示页
- A6：未登录仍可 `POST /offer`；原 `web/` 不变

# 约束与不变量

- 工作区：`.worktrees/admin-live-console`
- 演示会话计入全局 `max_session`（与原 `/offer` 相同）
- 单测不依赖 GPU 真推流

# 决策

- 隔离：独立 worktree
- 不整页搬原站；只复用连接与 echo 说话路径
- 演示从首页拆到独立页，首页只留待办
- 形象从管理员形象列表选择，不自动选第一项；信令复用原站接口
- 上传/录制/动作仍走「打开 /」
