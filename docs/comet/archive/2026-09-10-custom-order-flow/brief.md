# 目标

普通用户在「定制数字人」页提交素材与文案，形成订单；管理员接单后用现有 Avatar 生成管线产出形象，并自动绑定到该用户订阅。用户不直接占用 GPU 生成。

# 范围

- 订单表与状态机：已提交 → 已接单 → 生成中 → 已交付 / 已驳回；驳回后用户可再提交
- 用户可上传视频，或图片+音频，以及文字说明；素材落到 `data/uploads/orders/<order_id>/`
- 管理员在管理后台看到订单队列：接单、驳回（须填原因）、从订单启动生成任务
- 生成成功后写入形象元数据，并给下单用户绑定订阅（默认不发布）
- 普通用户禁止调用 `POST /api/avatar/task`（该接口改为仅管理员）
- 用户壳「定制数字人」从占位改为表单 + 我的订单列表
- 管理后台增加订单 Tab；管理员 Avatar 生成页可为某张订单创建任务

# 非目标

- 不实现图+音频自动变口型（一期只收素材；生成仍走现有视频抽帧）
- 不改用户首页连麦、不代理 TTS、不收紧旧 `/offer` 匿名
- 不支付、不开放自助注册

# 验收示例

- A1：普通用户登录后可提交订单（视频或图片+音频+文字）；未登录或管理员提交用户下单接口返回 401/403
- A2：用户只能看到自己的订单；不能调用 `POST /api/avatar/task`（401 未登录或 403 非管理员）
- A3：管理员可接单或驳回；驳回后用户能看到原因
- A4：管理员从已接单订单启动生成，任务成功后订单变为已交付，该用户资产中出现新形象且未自动发布
- A5：缺少视频的图+音频订单仍可提交并被接单；管理员若在无视频时点生成，得到明确错误而不是空跑 GPU
- A6：原 `web/` 与用户资产/发布行为保持可用

# 约束与不变量

- 工作区：`.worktrees/custom-order-flow`，基于已合入 main 的第一期代码
- 上传校验：类型与大小限制；禁止用户指定任意服务器 `video_path`
- 每用户同时进行中的订单数量有上限（默认 5 个非终态）
- 密码与引导账号规则沿用 auth-rbac

# 决策

- 定制只走订单，用户不直接生成（第一期已确认）
- 图+音频只作为订单素材与音色/形象参考；真正 genavatar 仍要视频
- 交付后自动订阅、不自动发布
- 旧 `/api/avatar/task` 改为仅管理员，避免匿名生成
