# 目标

管理员在管理后台可以对普通用户点「改密」（经确认后输入新密码）。活跃或已禁用均可。新密码立即生效，旧密码不能再登录，该用户全部平台会话失效。不能给管理员或当前登录账号改密。用户自己改密仍走顶栏。

# 范围

- `POST /api/v1/admin/users/{user_id}/password`：仅 `role=user`；请求体 `{ "password" }`，至少 6 位；成功后更新哈希并删除该用户全部 sessions
- 管理后台用户表：普通用户行显示改密按钮（确认后输入新密码）；管理员行没有
- 更新 `auth-rbac`、壳层管理后台一句，以及 README / README-EN 管理员说明

# 非目标

- 不自助注册、不邮箱、不忘记密码
- 不改 `web/`，不改用户/管理员顶栏自己改密
- 不恢复幽灵 change `omni-local-tts`

# 验收示例

- A1：管理员为活跃普通用户设新密码后，旧密码登录失败（与错误密码同一文案），新密码可以；该用户原有会话失效
- A2：已禁用用户也可改密；启用后须用新密码登录。改管理员、当前登录账号或不存在的 id 失败；未登录 401，普通用户 403；新密码少于 6 位被拒绝且哈希不变
- A3：普通用户行有改密按钮并经确认后输入新密码；管理员行没有
- A4：原 `web/` 无改动；顶栏自己改密行为不变

# 约束与不变量

- 工作区：main 当前目录（`isolation: current`）
- 新密码规则与开户相同：至少 6 个字符
- 代人改密后删除该用户全部平台登录会话
- 单测不连浏览器

# 决策

- 切片：管理员代人改密
- 隔离：当前目录 main
- 仅普通用户；活跃与已禁用均可
- 用户行「改密」按钮，确认后输入新密码
- 不要求管理员再输入自己的密码
- 接口形态对齐禁用/启用/删除：`POST .../password`，字段名与开户相同（`password`）
