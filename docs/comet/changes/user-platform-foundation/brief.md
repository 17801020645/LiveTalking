# 目标

把 LiveTalking 从「匿名演示引擎」变成可登录的双角色产品底座：管理员开户并给用户绑定数字人，普通用户在新前端只看到自己的订阅资产，并可把其中一个发布到首页。原 `web/` 演示站继续可匿名使用。

本 change 是二开路线图的第一期可交付切片。后续 change 再做订单生成闭环、用户连麦、TTS 代理与后端硬化。

# 范围

- 后端在现有 aiohttp 上增加 SQLite 用户库、登录 Cookie、角色（`admin` / `user`）
- 新认证 API 与资源 API 挂在 `/api/v1/*`；现有 `/offer`、`/human`、`/api/avatar/*`、`web/` 保持匿名可用
- 启动时扫描 `data/avatars/` 写入形象元数据；管理员可为用户绑定/解绑订阅
- 新建 `frontend/`：Vue 3 + Vite，生产构建挂到 `/app/`
- 登录后按角色进入不同壳：管理员四导航、普通用户三导航（未做能力显示占位）
- 普通用户「我的资产」列出订阅形象，可预览封面/静默片、将其中一个发布到首页（同时仅 1 个）
- 普通用户「首页」展示已发布形象的封面或预览片，不建立 WebRTC
- 首次无用户时，用环境变量创建引导管理员

# 非目标

- 不实现定制订单、管理员代生成、用户调用 `/api/avatar/task`
- 不把用户首页接到 WebRTC；不改口型推理与 TTS 插件
- 不代理 Omni `:8091`，不收紧旧接口 CORS，不持久化生成任务队列
- 不开放自助注册、不支付、不改原 `web/` 页面
- 不把生产默认入口从 `/` 改到 `/app/`

# 验收示例

- A1：无登录访问 `/app/` 受保护页时跳到登录页；错误密码不能进入
- A2：用引导管理员登录后进入管理员壳，左侧可见「首页 / Avatar 生成 / 管理后台 / TTS 语音管理」四项
- A3：普通用户登录后进入用户壳，左侧可见「首页 / 我的资产 / 定制数字人」；访问管理员 API 返回 403
- A4：管理员可创建普通用户，并把已扫描入库的形象绑定给该用户；未绑定形象不出现在该用户资产页
- A5：用户在资产页将某形象设为发布后，首页展示该形象；再发布另一个时首页只展示新的那个
- A6：未登录仍可打开 `/` 与 `/avatar.html`；`POST /offer` 与 `POST /api/avatar/task` 不要求登录
- A7：原 `web/` 文件未被改写；新 UI 只存在于 `frontend/` 与 `/app/`

# 约束与不变量

- 工作区为 worktree：`.worktrees/user-platform-foundation`，分支 `comet/user-platform-foundation`
- 密码不可明文存储；Cookie 为 httpOnly
- 每用户最多 1 条 `is_published=true` 的订阅
- 普通用户不能枚举未订阅 `avatar_id`
- 口令与引导账号不得写入 Git

# 决策

- 隔离：独立 worktree，与 `omni-local-tts` 并行
- 本 change 只做第一期：账号鉴权 + Vue 双角色壳 + 订阅资产与发布
- 定制流程（全局产品）：用户只下单、管理员生成；该闭环不在本 change
- 新前端：Vue 3 + Vite，目录 `frontend/`，路由前缀 `/app/`
- `/` 仍指向原 `web/`；新旧前端并存
- 旧业务接口保持匿名，避免原演示站失效；新能力走 `/api/v1/*`
- 关闭自助注册；管理员开户；引导管理员来自环境变量
- 用户首页一期只展示已发布形象，不连麦；「定制数字人」「Avatar 生成」「TTS」一期为占位页
- 资产预览优先用封面；若目录内已有 `preview.mp4` 则播放，本 change 不新生成预览片

# 待解决问题

无。用户已确认目标、第一期范围、非目标、验收项 A1–A7 与决策。

# 验证预期

- 不依赖 GPU：用测试库 + 本地 aiohttp 测登录、绑定、发布、403、旧接口仍匿名
- 有浏览器时：打开 `/app/` 走管理员/用户两条路径；对照 `/` 仍为原首页
- 验证时使用临时 SQLite 与引导账号环境变量，不碰生产密钥
