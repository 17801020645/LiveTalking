# 目标

已登录普通用户在 `/app` 首页对自己**已发布**的数字人建立 WebRTC，看到口型画面，并发送文字让它说话。资产页的静态预览与「同时只发布 1 个」沿用第一期。

# 范围

- 用户首页从封面占位改为：连接 / 断开、播放远端音视频、输入文字发送
- 新接口 `POST /api/v1/me/offer`：必须登录；形象固定为该用户当前已发布形象；忽略客户端传入的其它 `avatar`
- 说话仍走现有 `POST /human` + `sessionid`（与旧站兼容）
- 旧站点 `/` 与匿名 `POST /offer` 保持可用
- 管理员 `/app` 首页仍只链到旧 `/`，本 change 不做管理员连麦

# 非目标

- 不接入麦克风实时 ASR
- 不代理 Omni TTS，不改口型生成管线
- 不收紧旧 `/offer`、`/human` 的匿名（仍可用 sessionid）
- 不改原 `web/` 页面
- 不在本 change 做 healthz / CORS / 任务持久化
- 不开放自助注册、不支付

# 验收示例

- A1：未登录调用 `POST /api/v1/me/offer` 返回 401；已登录但没有已发布形象时，首页提示去资产页发布，且 offer 返回明确错误
- A2：用户发布一个形象后，首页可发起连接；服务端使用该已发布 `avatar_id`，请求体里其它 avatar 无效
- A3：连接成功后用户发送文字，请求带上本次 `sessionid` 到达现有 `/human`
- A4：对未订阅或未发布形象发起的连麦被拒绝
- A5：未登录仍可 `POST /offer`；原 `web/` 文件未被改写
- A6：管理员 `/app` 首页仍只有「打开 /」，没有连麦控件

# 约束与不变量

- 工作区：`.worktrees/user-home-webrtc`，基于已合入订单闭环的 main
- 每用户同时最多 1 条已发布订阅（已有）
- 新 offer 同时占用全局 `max_session`；同一登录用户同时只允许 1 路新接口会话
- 密码与引导账号规则沿用 auth-rbac

# 决策

- 隔离：独立 worktree，与 `omni-local-tts` 并行
- 首页只连当前已发布形象
- 互动：看画面 + 发文字（不做实时麦克风）
- 管理员首页不连麦，继续链到旧站
- 新 offer 必须登录；`/human` 仍用 sessionid，本 change 不收紧
- 旧 `/offer` 继续匿名
